# 视频提取油刹曲线（实验功能）

入口：**图像与数据 → 视频分析与标定**。只处理本地文件，视频不上传，不提取转向；全部输出为视频估算，不进入历史赛事、最快圈、领奖台或训练报告。

## 第一次使用：跟着三步操作

1. **视频与赛道**：点“选择文件”，等待自动预览。第一次保留“普通 POV”。从历史布局选择赛道；空列表会自动展开手动填写，使用游戏里的原始名称和米制长度。点“下一步：圈段与标定”。
2. **圈段与 HUD 标定**：拖动时间条并松手读取画面，在起点过线时点“设为圈起点”，下一次经过同一标线时点“设为圈终点”。核对是一整圈，再开启“我已核对完整一圈”；改动起终点后需要重新核对。精确输入可点“精确时间 / 旧标定”，展开时间输入，支持 `1:23.450`，点“读取当前时间帧”更新画面。
3. 按当前提示逐项标定：油门三点、刹车三点、固定文字拖框。每个圆弧依次点**几何圆心 → 真正 0% 起点 → 真正 100% 终点**，页面会逐点提示；无效圆弧留在当前项以便撤销。固定文字可用 KPH，不能用速度数字或挡位。主按钮会带你补齐缺失项，完成后进入“检查并提取”。
4. **检查并提取**：四项检查通过后点“开始提取”。普通 POV 可保持高级项收起；遥测模式展开同步条件。完成后点“打开结果”，先看缺口和质量说明，再按需比较已有结果或历史圈。

任何时候都可点“操作示意 / 帮助”查看圆弧示意、固定文字选择与纠错说明，支持鼠标滚轮和 PageUp / PageDown。误点用“撤销一步”，整项重新标用“重做本项”；覆盖线方向或宽度不合适时展开“方向与弧宽”。复用旧标定后仍须核对圈段和覆盖线。

首次使用引导仅负责页面准备检查，开始提取时仍执行原有完整验证；可读率不能代替正确率。没有同圈原生遥测时，不宣称绝对识别精度。


v0.2.42 预览按路径、大小、修改时间和工具目录复用元数据；最多暂存 3 张预览图、合计不超过 12 MiB，仅保留在内存中，换视频或关闭窗口释放。v0.2.45 当前帧保留原始分辨率，超过 12 MiB 的单帧不额外放入缓存；高倍缩放只上传可见区域及少量边缘，不生成整张巨型 Tk 位图。拖动预览条时只提交最新请求，过时帧不再刷新画面；文件变化后重新读取。“适合视窗”随窗口尺寸调整；手动放大后切帧保留缩放与视区。清除标定可撤销，任务运行中不允许清除；方向键不会选中当前模式不可用的标定项。

高频切页只移动页签指示线，页面内容和标定坐标保持稳定；预览不再反复触发完整提取的成功提示。进度反馈收敛到 120 ms；键盘与减少动态效果设置保持直接切换。网页报告鼠标读数使用时间 / 距离索引，并把同帧事件合并；按压反馈只响应指针操作，减少动态效果时不缩放按钮。

密集报告的显示采样同时保留油门、刹车和同圈遥测的峰谷、缺失边界及实际帧空档，不把显示降载后的时间间隔误判为解码缺口。显示点数是目标值，缺口边界较多时允许超出；CSV / JSON 中的完整提取行不改变。锚点可见性检查改用等价的整数方差比较，原识别阈值和估算语义保留；这些优化不等于提高绝对识别精度。

v0.2.37 使用三个独立步骤导航，填写内容在切换时保留。按钮按下、输入焦点、开关和进度提供短暂反馈；键盘操作与 Windows 减少动态效果设置会直接切换状态。标定图片和坐标保持稳定，新增“适合视窗”；小窗口自动缩紧标题并重排工具区。空闲时该窗口不保留进度轮询和动画定时器。

v0.2.39 选择视频后会自动读取预览与时长。普通视频保持默认输入条件；文件名中的赛道只能对应一个已记录布局时自动带入，多布局需手动确认。在第 2 步拖动预览条，松手后解码一帧，使用“设为圈起点 / 终点”代替反复输入秒数；这是手动确定过线位置，不能自动判断完整圈。选择终点后会自动将标定帧移回圈内。

油门 → 刹车 → 固定文字逐项引导，完成一项自动进入下一项，误点可“撤销一步”。成功提取后保存少量 HUD 草稿：同分辨率且固定文字匹配时自动带入，仍应核对圆弧覆盖线、方向与满量程。草稿只含几何与固定文字灰度模板，不含视频路径、视频内容哈希或完整视频帧，总量最多 32 KiB / 6 项。布局手填和 FFmpeg 目录按需展开；高级同步 / 地标不影响普通时间轴流程。

## 准备

- 在本机安装 FFmpeg，确保 `ffmpeg` 和 `ffprobe` 可在 PATH 找到；也可在界面选择同时包含两者的文件夹。插件不自动下载外部程序。官方入口：[FFmpeg 下载](https://ffmpeg.org/download.html)。这台开发电脑已配置这两个工具。
- 距离 HUD 模式使用 Windows 自带 OCR，经 Windows PowerShell 调用，不安装 AI 模型。如果系统缺少 OCR 语言包或 OCR 运行失败，结果保留时间轴并说明降级原因。API 来源：[Microsoft OcrEngine](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)。
- 选择一段原速、无剪辑、没有暂停 / 回放切换的完整单圈。HUD 位置、缩放与颜色固定，油刹弧不被字幕、鼠标或其他叠加层遮挡。支持约 4K 及以下画面（总像素不超过 4096 × 2160），最长 30 分钟，分析上限 30 Hz；建议原视频至少 30 fps，优先 60 fps。高分辨率视频会增加解码开销。
- 停止 HUD 记录后再提取。开始 HUD 时会取消正在进行的视频任务；关闭分析窗口或主程序也会取消。

## 一、选择输入条件

| 输入条件 | 可用分析 | 额外要求 |
| --- | --- | --- |
| 普通 POV | 时间轴油刹、固定地标分段耗时 | 至少两份结果分别填写两个以上同名固定地标，才能比较分段 |
| 视频含赛道距离与圈内计时 HUD | 时间轴、有条件的距离轴与距离时间差 | 距离是从本圈起点起算的游戏赛道进度，计时是本圈实际计时，均清楚可读、时钟一致 |
| 视频 + 同圈遥测 | 距离映射、同步残差、油刹误差、距离时间差 | 插件导出的已验证完整圈 `.lap.json`，明确同一圈，并填写至少两个同步点 |

只有一圈的开始 / 结束时间和赛道总长不能推出真实距离。这里不会用平均速度或速度积分伪造游戏赛道进度。

## 二、选择视频、圈段和布局

1. 选择本地 MP4 / MKV / MOV 等视频。开始、结束与标定帧时间都使用**视频内时间**，可填 `83.450`、`1:23.450` 或 `0:01:23.450`。
2. 填写赛道、具体布局原始名称与长度。历史布局下拉可直接带入已记录身份；不要把同一赛道的完整、短布局、无减速弯布局混用。遥测模式选择 `.lap.json` 会带入该圈的原始名称和长度。
3. 选择单圈内一帧 HUD 清楚可见的画面，点击“读取当前时间帧”。标定位置按未自动旋转的原始视频画面计算。

## 三、标定圆弧与可见性

在“HUD 标定”页选择油门，依次点击**圆心 → 0% 圆弧起点 → 100% 圆弧终点**；再标定刹车。校准线应覆盖绿色 / 红色输入弧的中心，避免白色转速环、轮胎图标和转向元素。分别设置顺 / 逆时针，弧宽使用原图像素（通常先试 6）。观察到的最高刹车不一定等于 100%，必须使用 HUD 真正的满量程端点。

选择“固定文字锚点”，拖框圈住始终不变的文字，例如 **KPH**。不要框挡位、车速、轮胎状态或会变化的背景。程序用锚点判断 HUD 是否可见：缺失时该帧油刹为空，不记成 0。这个检查不能识别所有遮挡，因此报告仍需人工核对。

画面支持 0.1–12 倍缩放。滚轮围绕鼠标所在位置缩放；按住右键或中键直接拖动画面，Shift + 滚轮横移。点过画面后可按住空格再左键拖动，平移不会增加标定点；滚动条仍可使用。预览时间条旁的 ±0.02s 按钮可细调，展开精确时间后还有 ±1 秒。已标定项会画出覆盖线；“重做本项”只重置当前项。提取成功后保存 `calibration.json`，下次可复用，但要求视频分辨率、HUD 缩放与位置一致，必须重新检查。

## 四、各模式补充设置

**普通 POV：**不必设置距离 / 计时读数。需要比较弯道分段时，在第 3 步展开“同步、地标与提取选项（可选）”后按顺序填写：

```text
T1入口标线 = 0:23.450
T1出口标线 = 0:28.800
T2入口标线 = 0:35.200
```

另一圈使用相同名称与相同物理位置、相同过线判据，允许视频时间不同。不要以各自刹车点、各自弯心作为对齐基准。地标必须位于该圈选段内。

**距离与计时 HUD：**在标定页分别框选距离纯数值与 `m:ss.xxx` 格式的圈内计时。距离单位明确选择 m 或 km。不能用当前车速、总行驶里程、预测圈时替代。OCR 约 5 Hz，异常数字、倒退、冻结和不合理跳变被排除；要求至少 10 个通过检查的观测，覆盖 95% 以上圈长，相邻观测空档不超过 1 秒。未通过时保留时间轴，禁用距离对比；缺口不外推。

**同圈遥测：**使用圈速对比导出的已验证完整圈 `.lap.json`；官方 DuckDB 需先通过插件“导入官方遥测”导入，再导出完整圈。原始时间 / 距离必须连续，赛道、具体布局和长度一致，不接受进站圈或无效圈。文件上限 1 GiB、圈时上限 30 分钟，不要选择整场 JSON。遥测通过流式读取，视频同步参考最多保留 60 Hz 的四列紧凑数值；不加载其他遥测大矩阵，也不改写原始高频数据。这个参考只用于最高 30 Hz 视频的估算比较，不代替完整原生分析。

同步点示例（假设视频 10 秒处为本圈起点）：

```text
10.000 = 0.000
60.000 = 50.000
110.000 = 100.000
```

至少两点且覆盖 80% 以上圈时；建议三个以上独立事件。左右分别是视频时间和遥测圈内时间。同步速率差超过 2%、残差超过 0.1 秒或整圈边界明显不匹配时拒绝处理。两点拟合不能独立验证漂移；手动同步本身也有误差。蓝 / 紫虚线为原始遥测的游戏过滤后油刹，可与视频弧比较；HUD 显示延迟可能使误差变大。

## 五、结果与比较

提取输出位于数据目录的 `VideoCurves/日期-编号/`：

- `report.html`：独立网页，时间 / 距离轴、鼠标读数、范围缩放和质量说明。
- `curve.csv`：完整提取采样，空值表示无法识别；包含真实 `video_pts_s`，不包含转向列。
- `curve.json`：结构化结果与身份、质量、来源。`source` 固定为 `video_hud_estimate`。
- `calibration.json`：可复用的几何标定及配置，不含视频绝对路径。

点击“比较两份提取结果”，依次选择 A、B 的 `curve.json`。同名固定地标生成分段表；两份结果都通过距离检查时生成累计 Δ 曲线。**Δ = B − A，负值表示 B 更快**。赛道、布局和长度必须相同；不同车型允许比较，但应由用户核对车况、天气等条件，报告不会推导驾驶能力高低。

### 与已有历史圈速对比

在视频窗口点击 **对比历史圈速**：提取刚完成时直接使用本次结果，否则选择之前的 `curve.json`。列表只读取同赛道的已导出最快圈和 `SelectedLaps` 中已导出的有效完整圈，优先同布局、默认时间最新优先；不扫描所有赛事的原始 CSV。还可通过“选择 .lap.json”加载其他已导出的有效完整圈。尚未导出的圈先在赛事复盘中选择圈号并导出；进站、无效和未验证旧圈不参与。

选择历史圈和输入通道（游戏过滤后 / 原始），点击“生成历史圈对比”，再点“打开对比报告”。A 为视频估算的绿 / 红实线，B 为历史遥测的蓝 / 紫虚线，悬停可同时读两圈输入。比较的是不同单圈，与“视频 + 同圈遥测”的同步标定用途不同，后者必须确实来自视频中的同一圈。

普通 POV 只对齐圈起点并保留各自真实时间，不拉伸较慢的圈，也不从圈时和赛道长度生成距离；同一时刻未必在同一位置。布局或长度标注不同会提示：只有人工核对物理布局相同，才可勾选“确认视频采用所选历史布局”；该关联只作用于此次时间轴报告，保留旧标注，不修改源文件。已具有距离数据的视频禁止这种跨身份重绑定。

只有双方实际距离都通过覆盖与连续性检查且身份一致，才提供距离轴及累计 Δ。视频已填写固定地标时，可在历史对比窗口按相同名称填写历史圈内时间，生成分段表。未经同位置校准时，不根据时间轴曲线的位置差给出逐弯损失结论。

中断只清理当前临时产物，原视频、原遥测、历史赛事和先前成功结果保留。视频不计算 SHA-256 等内容校验。处理采用逐帧 ROI 流，输出采样最多 54,000 行，不缓存整段视频；解码器仍需缓存少量原分辨率参考帧，不能把这理解成固定的极低总内存。

## 精度与当前验证边界

这是**实验功能**：已使用合成视频验证信号、时间、距离和遮挡，并以真实富士 POV 视频跑通提取、GUI / CLI 与交互报告。实录抽检仍存在力度差异，尚未用同圈原始遥测验收绝对精度。结果一律标记为估算；通过连续性检查不等于通过精度认证。

- 帧时间采用 FFmpeg 实际选择帧的 PTS，支持变帧率输入，避免用帧号 / 名义 FPS 代替真实时间。实现依据：[FFmpeg select / showinfo](https://ffmpeg.org/ffmpeg-filters.html)。
- 颜色压缩、缩放、弧宽、HUD 更新率与显示延迟会影响油刹量化。`confidence` 是圆弧填充连续性分数，**不是识别正确率**；可见性锚点也可能误判。
- OCR 读数分辨率、约 5 Hz 更新、最多 1 秒允许插值空档，以及手动同步误差都会影响距离时间差。不得据此声称精确到百分之一秒的逐弯增益。
- 精度验收需要同一圈同步视频与原始遥测，覆盖不同油刹量、分辨率、帧率与遮挡，核对每弯距离误差、时间误差和缺失率；未经验证不升级为已验证原生数据。

## CLI

源码环境可复用界面保存的标定，不必再次打开标定窗口：

```powershell
.venv\Scripts\python.exe tools\analyze_video.py --config "标定文件目录\calibration.json" --video "视频目录\lap.mp4"
```

可选 `--output-root` 指定独立数据根目录、`--ffmpeg-dir` 指定工具目录；遥测模式还需 `--telemetry "单圈目录\selected.lap.json"`。Ctrl+C 取消当前处理。所有路径都指向本机，不支持网络视频链接。

便携版也支持同样的参数：

```powershell
.\LMU-Stintrix.exe --analyze-video --config "标定文件目录\calibration.json" --video "视频目录\lap.mp4"
```

便携 EXE 没有控制台窗口，成功时生成独立结果目录，失败时在输出数据根目录留下 `video_cli_error.txt`；正常图形界面仍有进度和取消按钮。

已提取结果与历史圈比较，无需再次解码视频：

```powershell
.\LMU-Stintrix.exe --analyze-video --compare-result "提取结果\curve.json" --reference-lap "历史圈\selected.lap.json" --channel filtered
```

`--channel raw` 选择原始输入。只有确认视频与所选历史圈实际布局相同、但标注不同的普通时间轴结果，才使用 `--bind-history-layout` 显式关联；禁止用它跨布局制造距离差。新报告保存在独立 `VideoCurves/History-编号/`。

## v0.2.45 标定操作改进

滚轮缩放支持高精度滚轮增量，并保持鼠标下的原视频位置；右键／中键或空格＋左键直接平移，Shift＋滚轮横移。“适合视窗”恢复全图；切帧保留手动缩放与视区。放大使用当前原始分辨率帧的可见裁片，不会先缩到1120像素再放大，也不插值伪造视频细节。时间条旁可±0.02秒细调；预览解码忙时，连续定位只提交最新目标。

先找踏板正在踩下的画面再标定。部分LMU HUD的绿色油门与红色刹车都在左侧，半径不同；右侧外环可能是转速，不要按左右猜测。分别核对三点、方向和覆盖线，再使用“检查标定”；当前踏板为零不能证明标定正确。


### 可选 120 Hz 平滑曲线

在第三步的「提取选项」勾选「另存 120 Hz 平滑曲线」，或 CLI 添加 `--smooth-120hz`。保持原始 CSV / JSON 不变，另存 `curve_120hz.csv`、`curve_120hz.json` 与 `report_120hz.html`。报告可切换原始样本与插值曲线。

采用 PCHIP 保形插值，按真实时间戳生成每秒 120 个等间隔点，限制在 0–100%，不跨越 HUD 缺失、无效通道或超限帧间隔，也不外推。它不会恢复低帧率遗漏的细节或增加原始精度；原视频帧率可以不同，但必须能解码并识别 HUD。距离对比及原生成绩继续使用原始数据。单点不延伸；低帧率导致的长间隔会保留缺口。

已有结果可运行 `python tools/analyze_video.py --resample-result <curve.json>`，不需要重新解码视频。该操作只写入同目录的三个独立插值文件，不改写原始数据与报告。


### 实际频率与重新打开结果

提取按目标时间网格选择真实视频帧，保留实际 PTS；低帧率或可变帧率视频不会通过复制帧伪造采样率。报告显示目标提取频率与实际原始频率；120 Hz 输出另标为插值估算。

「图像与数据」及视频分析页均提供「最近提取结果」，无需重新选择视频就能打开原始报告、120 Hz 报告或结果目录。列表最多显示最近 100 个可用结果，旧结果也能读取；仅解析元数据头，不扫描样本数组。缺失 / 损坏的结果会跳过，原始文件保持不变。新结果中的 `video_result_summary.json` 只作本地摘要，不上传 GitHub。
