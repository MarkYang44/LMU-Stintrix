# 完整保留数据时，怎样减少存储

## v0.2.40 已实现

**入口：图像与数据 → 无损节省磁盘空间。** 赛后自动压缩和新赛事分块列式存储默认开启；只有记录完整结束、报告步骤结束后才转换，录制与检查点仍顺序写普通 CSV。关闭“新赛事使用分块列式存储”可让新记录继续使用 CSV / LZX。历史赛事不会自动批量迁移。

- **分块列式格式 `.csv.stc`**：每块最多 2048 行或约 2 MiB 原始字段，列独立压缩，按列自适应选择完全相同值游程或无损字节前缀差分。保留原始字段字节，包括小数表达、负零、空值、引号、UTF-8、时间戳和行结束符。没有转成 float32、取整、降采样或删点。索引支持选择列与行范围，复盘输入读取已使用列投影。
- 转换单次读取原 CSV，关闭较小的临时文件后原子替换，再移除冗余 CSV；收益不足时保留原文件。没有文件内容哈希、转换后回读或全量比较；只用大小 / 修改时间防止转换期间源文件被同时写入。中断未完成时保留原 CSV。转换失败不影响之前已生成的报告和原始记录。
- **兼容与恢复**：插件的最快圈、训练、领奖台、赛事分析和报告读取通过适配器按块还原；旧 CSV 照常读取。选中赛事后可“导出原始 CSV”到新目录，或“恢复选中赛事为 CSV”在原目录恢复并移除列式文件。旧版本插件与外部直接读 CSV 的工具应先恢复 CSV。ZIP / 7z 导出包含普通 CSV，不要求接收者理解 `.stc`；自动导入无哈希 v2 清单需 v0.2.40 或更新版本，旧版可用通用解压工具提取其中的普通记录文件。
- **缓存容量**：可重建训练与派生最快圈缓存默认合计 512 MiB，可调整。仅淘汰程序生成的缓存目录，避开同进程正在使用的缓存；后台独立报告进程不执行淘汰。菜单空闲时整理，界面“缓存与导出文件”也有“按上限整理”。正在使用的缓存可能暂时使总量超过限额；下次使用已淘汰缓存时会重新计算。
- **报告资源共享**：今后生成的本地复盘与自动最快圈页复用不可变脚本，NTFS 上用硬链接避免重复占用，其他文件系统退回复制。每场目录带有 `.stintrix-assets` 配套资源，整场移动和归档仍可离线使用。只分享一张复盘 HTML 时使用“导出独立复盘页”；对比页的“保存对比页”会内嵌脚本，继续生成独立 HTML。旧报告不批量重写。
- **同圈与导出去重**：同一已结束赛事的最快圈 CSV 与手动选中该圈的 CSV 可共用不可变文件内容；重新生成使用原子替换，不会修改旧链接快照。重复选择相同圈号或导出同版本赛事包时，按来源与元数据复用已有输出，不扫描文件内容。用户主动修改、原数据或导出资源版本变化时生成新结果。独立单圈 JSON 仍完整导出，保留与外部工具的兼容性。
- **无内容校验归档**：新比赛包使用 v2 清单，不存 SHA-256，不在导出完成后再完整解压回读。导入兼容旧 v1 清单，但不核对内容哈希；旧 `verify` 参数不重新开启该扫描。仍保留格式解析、安全路径、容量限制和压缩格式自身的正常解码。相同包按导入收据与元数据复用已有结果，不声称通过完整性认证。
- 仅自动回收本程序列式转换产生的、超过一天且所属进程已退出的临时文件；用户报告、图片、视频、训练目标和未知文件保留。

实录副本体积测量：371,236 行、34 列、约 97.08 MiB 的 CSV 转为 182 个块后约 9.99 MiB。原有 LZX 占用约 14.16 MiB，额外减少约 29.4%；转换约 15 秒，在记录结束后执行。数字只代表这一份数据与本机，不保证其他赛事有相同比例。原文件未转换或覆盖，也没有对该实录执行内容核验。

官方遥测导入与指南资源的原有完整性保护保留；本轮新存储、缓存、归档和复用路径不增加内容核验。相关数据接口的格式、范围与单位处理仍保留，避免把错误单位当作有效分析。

## 当前已经启用的方式

完整赛事与报告保存结束后，Windows NTFS 每文件 LZX 透明无损压缩默认开启。路径、文件内容、采样数量、精度和读写接口保持原样；录制采样线程不执行压缩，不逐文件计算内容哈希。界面入口为“图像与数据 → 无损节省磁盘空间”。文件属性中的“占用空间”反映真实节省，“大小”仍是解压后的逻辑大小。

本机一次只读评估：371,236 行 CSV 的逻辑大小 97.08 MiB，当前实际占用 14.16 MiB，节省约 85.4%。同文件以流式 gzip 测量为 16.33 MiB，并逐块解码与原字节比较一致；没有生成额外压缩副本，没有改写原文件。这是单份样本，不能保证所有赛事达到相同比例，也不能把它当作进一步可节省的空间。

## 平直部分只保留端点是否无损

如果某一通道的中间值**完全相同**，可用起始样本索引、连续样本数、原值记录一段游程（RLE），读取时还原原来的每一个值。必须另外保留完整时间轴、缺失值、事件状态和其他独立通道。不能以固定采样率假设替代实际时间戳。

油刹不变并不代表整行采样不变：速度、赛道距离、轮胎温度与磨损、车辆姿态、油量、ABS / TC 状态仍会变化。本次样本原始油门连续重复约 81.4%，刹车约 85.3%，转向只有约 0.5%；“方向看上去没打”不等于转向数值完全不变。以上比例是可重复值的数量比例，不代表对已压缩文件的额外字节节省。

“接近直线就删点”、忽略小转向、取整或设置误差阈值，都会损失采样信息。用两个端点插值也无法保证还原中间的尖峰、短促松刹、输入变化时刻或距离时间差。因此本版不对历史记录和采样文件启用删点。

## 进一步可评估的方向

- 当前列式格式已经使用游程和字节前缀差分；后续仍可比较字典编码等方法，但不能预先保证比现有方式更小。
- 索引只保存赛道、布局、日期和圈号等小字段，需要时流式读取被选中的圈；避免在多个缓存中复制整场采样。
- 多个网页共享同一份曲线数据可减少重复，但会引入配套文件依赖；当前独立 HTML 的分享能力应保留，不能单纯为省空间破坏它。
- PNG / JPEG / WebP 图片和原视频继续保留原版，不二次有损重编码。较少使用的赛事可用现有 ZIP / 7z 包冷归档；只有主动移走原记录才能减少工作目录总量，保留两份则不会省空间。

绘图可使用峰谷包络等派生数据加快显示；这只能作为显示缓存，完整源采样继续用于分析和导出。
